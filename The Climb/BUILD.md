## Purpose

Use small engineering exercises to turn knowledge into explainable capability. This is a supporting workbench, not a third career campaign or an extra mandatory daily quota.

## Milestones

| Point | Target picture | Evidence |
|---|---|---|
| **A · Oct 21** | Choose one gap worth demonstrating | A bounded exercise with a testable finish condition |
| **B · Oct 31** | Complete one focused slice | Working behavior and tests, with decisions explained |
| **C · Nov 30** | Apply a second related concept or real interview weakness | Demonstration plus failure-path reasoning |
| **D · Jan 31** | Explain the engineering decisions under follow-up questions | A short walkthrough and trade-offs |
| **E · Apr 4** | Practical confidence supported by work, not only reading | A few well-understood exercises or a selected product contribution |

## Candidate slices

An idempotent background job; a small retrieval/evaluation pipeline; an API with tenant authorization; a React workflow with clear state/error handling. These are practice options, not claims that you implemented them in a prior job.

Choose one only when it improves current Prep or Own Build. Budget it inside that department's time, keep executable project trees outside the vault, and record the exact external working path when a build is actually started.
