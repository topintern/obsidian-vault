Samay Systems: Compliance automation. The structure was like we onboard tenants (like companies) and tenants have orgs (org A, org B etc.), tenants can sign in and view dashboard, compliance info, framework satisfaction, integrations, query chatbot visualize relationships, user access footprints etc. Original plan was to do it with completely with python - lambda architecture,have a system that collects, analyses and determines compliance according to the documentation of the three frameworks (SOC2, NIST, ISO27001) Started off with the Integrations module Developed Github, JIRA, Azure integrations, with slack, okta and some others in the pipeline Users can create connect their integrations, trigger scheduler which collects evidence data from all their integrations and later dashboard and validation use cases, they can see sync status, change api keys etc. Developed policies module where users can upload diff policy docs, developed in house quill based editor with version control to see, edit, revise and upload docs. Handled diff conversion losses for docx, pdf, rtf etc. Developed entire controls module, where users can see the controls of their subscribed framework, how much each control is sbeing satisfied, control detail page where they can submit evidences, see or trigger automated runs, comments section and etc. Worked on RAG and neo4j + graphql based NL to cypher query converting chatbot which takes users queries and gives back the knowledge / relations graph for users to analyse compliance relationships. Manually crafted automated tests for diff compliance controls for all the diff available integrations Built n8n workflows to generate daily compliance summary reports using agentic AI and mcp based tool calling. Worked on with AWS, VPC, AWS CDK, CLI based deployments. Helped with db schema restructuring to support multi-tenancy and dynamic resolution, and migrations to graphQL based schema and endpoints for some modules. Monarch Tractor: Requirement was to build a workflow that automates the data from a 3 rd party HRMS system like UKG into an SSO like jumpcloud where various user groups are present, devices are monitored, provisioned, onboarded and offboarded from, similarly from jumpcloud into azure AD where licenses are provisioned, and an active directory is maintained for other purposes. So basically, data must remain consistent across the three databases, the entry point being the 3 rd party HRMS UKG. Again, data can’t be pushed or updated into UKG. So UKG must be the source for the other two. Now discussions went on for the approach, what technology, what vendor to use etc. decided between three vendors workato, boomi or AWS for API integration, had calls with vendors, based on our budget decided to go with AWS. Wrote python scripts hitting the three APIs, fetching data, used S3 to store and receive data between scripts, AWS secrets manager to store and fetch credentials securely, AWS Lambda to run the scripts, CloudWatch to log the events, and event bridge to schedule and run the events on a regular basis. Implemented the workflow from start to finish, as soon as a new record/user appears in UKG database, it is scanned periodically to create/update/delete the user in jumpcloud as well as Azure AD in synchrony. For new users at the end of the workflow an automated welcome email is also sent. Some Challenges I Faced: so again I had run into a little trouble with AWS lambda being not so flexible, did not have much except basic packages and had to add a layer for all of the extra libraries I wanted, I had to implement a PowerShell script in lambda, and AWS lambda was very restrictive in terns even in terms of size if the layer, so I had to execute a lot of command in PowerShell, leaving all the main libraries i needed like exchange inline etc., Nd even basic commands required helper libraries! So, layers was not a viable solution! so I had to create it from an container with all the dependencies installed! Another one was one of API endpoint was not working properly on UKG side, So I raised a ticket to UKG and mentioned there was a problem, I needed this info and this API endpoint was not working, so they addressed the gap later. I encountered various other challenges, such as handling API rate limits, managing data transformations, and implementing error handling mechanisms. By applying my CS education, I devised innovative approaches to tackle these issues and ensured the automation solution's effectiveness and reliability.
