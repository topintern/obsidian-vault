## Every story answers

Problem → actual constraints → my contribution vs team's → system/data flow → hard decision → failure/testing/observability → defensible outcome → what I would change.

Keep these labels explicit: **remembered**, **supported**, **uncertain**, **proposed improvement**. A proposed design is not something already shipped.

## Behavioral branches

Ownership · ambiguity · disagreement · failure/recovery · delivering under constraints · learning quickly. Start with [[The Climb/Practice/Q12 - A difficult technical decision|a difficult technical decision]]. Use 60–90 seconds first; technical deep dives follow only when asked.

This is part of the Prep time budget, not an extra daily hour silently added to it.
